# CLAUDE.md

Учебный проект с курса Hexlet по вайбкодингу. Основное содержимое — веб-калькулятор калорий на чистом HTML/CSS/JS: расчёт дневной нормы и дневник питания.

## Стек и ограничения

- Без сборки, без `package.json`, без зависимостей и фреймворков. Не добавляй их без явной просьбы.
- Нативные ES-модули (`<script type="module">`), поэтому через `file://` приложение не работает — нужен локальный сервер.
- Весь пользовательский текст, комментарии в коде и названия тестов — на русском.

## Запуск

```bash
python3 -m http.server 8080
```

- Приложение: http://localhost:8080
- Тесты: http://localhost:8080/tests/ — на странице выводится «Пройдено N из M», результаты также доступны в `window.testResults`.

Конфигурация запуска для превью лежит в `.claude/launch.json` (тот же сервер на порту 8080).

Прогон тестов без браузерного окна (сервер должен быть запущен, Playwright есть в окружении):

```bash
node -e "require('playwright').chromium.launch().then(async b=>{const p=await b.newPage();await p.goto('http://localhost:8080/tests/');await p.waitForFunction(()=>window.testResults);const r=await p.evaluate(()=>window.testResults);await b.close();const f=r.filter(t=>!t.ok);f.forEach(t=>console.log('✗',t.name,t.message));console.log(r.length-f.length+'/'+r.length);process.exit(f.length?1:0)})"
```

## Структура

```
index.html          — разметка обеих секций (норма и дневник)
css/styles.css      — стили; цвета через CSS-переменные в :root, тёмная тема через prefers-color-scheme
js/calc.js          — чистые функции расчёта и справочные константы (без DOM)
js/foods.js         — справочник продуктов FOODS, значения на 100 г
js/app.js           — DOM, обработчики форм, состояние и localStorage
tests/index.html    — самописный раннер тестов (assert.equal / assert.deepEqual)
tests/calc.test.js  — тесты для calc.js
```

## Архитектура

- **`js/calc.js`** — вся бизнес-логика. Функции чистые и не трогают DOM, чтобы их можно было тестировать:
  - `calcBmr` — базовый обмен по формуле Миффлина — Сан Жеора;
  - `calcDailyNorm` — BMR × коэффициент активности (`ACTIVITY_LEVELS`) × коэффициент цели (`GOALS`), плюс БЖУ;
  - `calcMacros` — делит калории по `MACRO_SPLIT` (30/30/40) с учётом `KCAL_PER_GRAM` (4/9/4);
  - `calcPortion` — пересчёт значений «на 100 г» на порцию;
  - `sumEntries` — итоги дневника;
  - `validateProfile` — возвращает объект `{ поле: сообщение }`, пустой объект — нет ошибок. Диапазоны в `LIMITS`.
- **Округление:** ккал — до целого, граммы БЖУ — до 0,1. Ожидаемые значения в тестах зависят от этого.
- **`js/app.js`** — один объект `state` (`profile`, `norm`, `entries`). После изменения: `saveState()`, затем `renderNorm()` / `renderDiary()`. Рендер полностью перестраивает список через `replaceChildren`.
- **Хранилище:** ключ `calorie-calc:v1` в `localStorage`, сохраняются `profile` и `entries` (норма пересчитывается при загрузке). Доступ к хранилищу обёрнут в `try/catch`. Если меняешь формат данных — повышай версию ключа.
- **Ошибки форм:** элемент `<small class="error" data-error="<name>">` рядом с полем; `showErrors(form, errors)` пишет туда сообщение и вешает класс `invalid` на одноимённое поле. Новое валидируемое поле должно следовать этой схеме.
- **Справочник:** при вводе названия, точно совпадающего с продуктом из `FOODS` (без учёта регистра), поля ккал/БЖУ заполняются автоматически. Новый продукт — объект `{ name, kcal, protein, fat, carbs }` в `js/foods.js`.

## Стиль кода

- 2 пробела, одинарные кавычки, точки с запятой, висячие запятые в многострочных литералах.
- Именованные экспорты, `const` и стрелочные функции; хелпер `$ = (id) => document.getElementById(id)`.
- DOM строится через `createElement` + `textContent`, не через `innerHTML` (в названиях продуктов — пользовательский ввод).
- Формы с `novalidate`: валидация только в JS.
- Новые цвета — только через CSS-переменные, с парой для тёмной темы.

## Правила при изменениях

- Новая логика расчёта — в `calc.js` и с тестом в `tests/calc.test.js` (объект `tests`: ключ — название теста на русском, значение — функция, принимающая `assert`).
- После изменений прогоняй тесты и проверяй приложение в браузере: консоль без ошибок, норма считается, запись в дневник добавляется.
- При изменении функциональности или структуры обновляй `README.md`.
- `temp.txt` — тестовый файл из экспериментов с GitHub-интеграцией, к приложению не относится.
- `.mcp.json` подключает GitHub MCP-сервер через переменную окружения `GITHUB_MCP_PAT` — токен в репозиторий не коммитить.
